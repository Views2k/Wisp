# Headless production-host fixture

Root owns compilation and execution. No product source is edited. This separate binary links the unchanged recorder host, scheduler, converter, selected encoder, real process-loopback audio source, audio timeline, AAC, spool and MP4 writer. Only `GameScreenCapture` is replaced at link time by generated GPU textures. Neither screen/window capture implementation is linked. There are no windows, focus/input changes, microphone, system-audio selection or arbitrary process targets.

`Build-SyntheticHostFixture.ps1 -OutputDirectory <fresh absolute checkout work directory>` defaults to the exact delivered `eb975e9d1565a7ec954464a3e6b8683500d7b770` native source archive, including its original spool behavior. `-Source current` is a separately identified later comparison. Every build uses a fresh source copy and records source/header/fixture/executable hashes. Do not call the baseline the installed executable: it is the installed revision's native pipeline plus a diagnostic source/controller.

The executable accepts only `--output <fresh absolute checkout work directory> --mode lossless|compressed`. Its private in-process pipes send fixed configuration: 2160p60, Q100, selected 30 seconds, process-loopback audio targeting itself, no system audio. A fixed opaque token replaces HWND only within the diagnostic backend; the product's FH6 identity checks are unchanged. Real QPC timestamps accompany a deterministic moving gradient/block texture. This moderate spatial complexity is not a measured substitute for gameplay entropy. The older SyntheticHdrFrameProvider is unsuitable because it produces converted 1080p output, bypassing the 2160p host conversion boundary.

One host epoch only: save once at 35 seconds after Start acknowledgment, then stop after the save result or at 45 seconds from process startup. No retries, threshold changes, artificial clock offsets or automatic recovery. An independent unconditional process deadline is 58 seconds, including cleanup. Apps-closed checks run before activation and every 250 ms. The target process is the fixture itself, which emits no playback, so accepted process-loopback packets contain its own silence. Success requires a saved MP4 with audio and normal stop; actual saved duration is in the unmodified protocol report.

The current-source `--pause-resume` arm instead records four seconds, requests Save and Pause, holds the paused capture for at least two seconds, saves again while paused, explicitly resumes the same target, records three more seconds, then pauses and saves a third time. Its soft deadline is 25 seconds. The production pause/resume, audio-source restart, timestamp mapping, codec state, spool and exports are unchanged. Only the explicit self-only capture adapter supplies identity/foreground checks and generated frames; production has no bypass. Completion requires no generated frames throughout the pause, all three audible saves, retained pre-pause start bounds, two to four seconds of additional media after resume (excluding the wall pause), and normal cleanup. The report separately records whether Pause was acknowledged before the first Save completed; a very fast export does not prove concurrent mux overlap. This remains a generated-source timing/lifecycle check, not a desktop privacy, real Forza audio, physical sync or performance measurement. Use a build from `-Source current` and preserve each MP4 for independent decode validation.

The explicit current-source build switch `-Hdr` substitutes a generated 1920×1080 FP16 linear-scRGB input and selects 1080p60 output. This build only accepts the bounded `--pause-resume` workload, in either compressed or lossless mode. The moving gradient contains linear values above SDR white and 600-nit moving bars; no desktop, display, game configuration or capture API is consulted. Every successful save must carry `hdrVideo:true`, in addition to the unchanged audio and retained-history checks. Build provenance and `fixture.json` identify the generated HDR input and output height. Independently decode all three MP4s and inspect their HEVC/PQ/BT.2020 metadata; this lifecycle fixture does not replace the fixed-palette pixel oracle or a displayed-pixel test.

The output must be a fresh local checkout `work` directory with held non-reparse ancestors and at least 16 GiB available. The production host may require more free space under its unchanged conservative lossless policy. Only this directory is enumerated through held directory handles, at most 8,192 entries and four levels. Children are opened relative to those handles with reparse traversal refused; actual file EOF comes from `GetFileSizeEx` while each verified regular-file handle is held. Share-delete permits normal host cleanup; only missing/deleted entries are skipped. Output size is sampled every 250 ms: request stop at 4 GiB, terminate at 6 GiB, and reject any observed total over 16 GiB. This intentionally large headroom bounds ordinary in-flight writes; it is a monitored diagnostic ceiling, not an OS disk quota or proof of arbitrary stalled-I/O behavior. No files are overwritten or removed by the fixture controller. The unchanged host can discard only its own completed temporary buffer during successful stop. Failure buffers remain for inspection.

Earlier reports used cached directory-listing sizes. The first current-source 8×8 run therefore understated open buffer files and did not enforce its claimed 4 GiB soft budget; preserve that run as timing evidence, not a passing storage-bound check. The CPU-only `--size-check --output <fresh absolute checkout work directory>` route verifies 8,192 then 73,728 bytes while the same buffered writer remains open, without flushing it. It writes under 128 KiB, uses a ten-second deadline, and activates no graphics, host, audio or capture. The resulting `size-check.json` distinguishes this check from a recorder run.

`protocol.jsonl` preserves canonical host state/results, including saved duration and size-limited state. `native-diagnostics.jsonl` preserves the existing fixed-token/scalar failure record, including stage, frame/packet counts, scheduler lag and audio clock residual. `fixture.json` records aggregate exit/save/cleanup facts. These contain no paths, PIDs, addresses or raw OS messages. Exit 124 is the unconditional deadline, 126 the emergency output ceiling, and 127 incomplete host cleanup. An early host failure is a result, not permission to retry blindly.

This exercises real host scheduling under encoder/audio/spool/mux load. The default build uses SDR input; only the explicit `-Hdr` build uses generated HDR input. Neither exercises Desktop Duplication, game focus transitions, Forza audio, managed recovery, playback, physical A/V synchronization or gameplay performance. A passing fixture cannot close those live-use requirements.

After the first fixture initialization failure, `--shader-check` provides a CPU-only, ten-second-bounded compiler comparison. It reconstructs the original shader by changing only the two `detail` identifiers back to `texture`, compiles both vertex/pixel entry points in each variant, and reports only HRESULTs. It succeeds only if the original fails and the corrected shader passes. No graphics device, audio, window, capture or file is opened by that route. Full-host initialization now records a fixed token for each failing API boundary instead of the previous generic token. This does not establish the failure cause until the compiler comparison is executed.

For an `-Hdr` build, the same CPU-only route instead reconstructs the three original `linear` identifiers from `radiance`. `linear` is an HLSL interpolation modifier and the original HDR fixture failed shader compilation. The comparison changes only that identifier and preserves the same failing-before/passing-after requirements. This diagnostic repair does not change the production converter.

The explicit `--mode lossless --pattern high-output` arm changes the synthetic detail to deterministic, frame-varying 2×2 cells. It keeps 2160p60/Q100, the selected 30-second history, all production source, real QPC timing, self audio, storage limits and guards. It requests no save and stops eight seconds after Start acknowledgment. Completion requires normal stop at that planned boundary, audio-enabled buffering and a status sample with at least six seconds retained; an early storage stop or reset is not a pass. The original baseline invocation remains unchanged. This short arm is intentionally not a 30-second retention/save test.

The separate `--mode lossless --pattern varying-8x8` arm uses the same frame-varying detail hash with 8×8 cells. It has the same eight-second/no-save completion rules, selected duration and storage limits as `high-output`. The default moving/static 8×8 baseline pattern is unchanged. Use exactly this same labeled workload for the delivered-source versus current-source Seal comparison; it aims to reach several GOP boundaries within the output budget. Its actual rate must be measured, not assumed to match gameplay.

Build provenance lists available variants; `fixture.json` identifies the selected variant, frame-varying cell side and stop trigger. Its throughput is the latest actual combined encoded-video/AAC payload divided by that buffer's media duration, derived from unchanged once-per-second host status. It is not raw source bandwidth, disk bandwidth or a promised match for the reported gameplay data rate. A source-complexity comparison cannot by itself prove a specific blocking API caused a scheduler reset.

Optional build switch `-Timing` adds exact-match observer hooks only to the extracted `RecorderHost.cpp` and `EncodedSpool.cpp` copies. Every anchor must match once or the build stops. The Seal anchor permits exactly one of the delivered flushing implementation or the reviewed current non-flushing implementation; instrumentation preserves that chosen behavior. The original copies, normalized-path unified diff and replacement inventory remain under the fresh build's `instrumentation` directory; provenance records both original and instrumented hashes. Repository production files are never patched by the build recipe. The timing define enables fixed-stage RAII observers around host phases, spool append/seal/flush/write/create/retain boundaries and freezes them on the first production `RememberFailure` call before cleanup.

Observers only query QPC and update fixed in-memory arrays on the host owner thread: count/total/max duration and byte counts for 17 stages, plus the latest 64 completed operations taking at least 1 ms. They perform no allocation, output, waits, locks or media modification. Other threads are ignored and counted. The fixture writes `timing.json` after all host-owned workers join. Completed nested scopes overlap and must not be summed; a scope still open at the failure is omitted. QPC observation has a small nonzero overhead. Source pattern, scheduling thresholds, audio rules and storage behavior are unchanged. Repeat the same workload before attributing a measured delay to a product operation.
