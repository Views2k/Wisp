Wisp 2.5.3 Clips Preview 2
Private build ID: clips-preview-20260930-02

This private candidate adds Clips and preserves the confirmed shift-coverage hotfix.
It uses your existing Wisp installation, local settings, calibrations and saved runs.
It is not a separate installation. It has not been published as a public release.

Clips
Open Clips between Extras and Release Notes. Choose a folder on a local drive,
then enable clipping. Save clip keeps the available recent recording. Clipping
is off by default, and recording settings can be changed while it is off.
The default is 60 seconds at 1080p60, quality 75. Lengths run from 30 to 300
seconds in 30-second steps. Select 360p through 2160p and 30 or 60 fps.
Higher quality and resolution use more storage. Five-minute clips take longer
to save and need more space. Recording also uses temporary space in that folder.
Choose a shorter folder path if Wisp says the location is too long for playback.
Existing clips in that folder remain available to browse and export.

Enable and assign the two shortcuts separately: toggle clipping and save a clip.
Saved clips appear 25 per page; the number of columns adapts to the window.
Click a clip to watch it. Export copies its recorded resolution and quality;
it cannot restore detail removed by compression or increase captured detail.
Dashboard reminders identify clips not yet viewed or exported. Storage or
recording errors still appear even when reminders are off.

Audio comes from the game process when supported, never your microphone or all
desktop audio. If game audio cannot start, the status explains the silent fallback.
Window capture may omit a separate Wisp HUD overlay. Full gameplay performance,
game audio, HDR appearance and five-minute recording still need live validation.
Offline and synthetic checks do not establish the requested under-5% FPS impact.

HUD profiles
Use Save current HUD as a profile after arranging your HUD. New and updated profiles
save positions as well as gauges, colors, units, driving guidance and run-recording controls.
Apply restores saved positions on matching displays and keeps windows on-screen.
Older profiles keep their original scope until you update them from the current HUD.
Calibration data, saved runs and application settings stay separate from profiles.

Runs > Lap review
Save completed laps automatically is off by default. Enable it to save detailed laps
locally while Wisp is running, including when the lap overlays are hidden.
Capture uses the lap timing mode selected in HUD settings. Wisp must observe a valid
start boundary and the following finish; partial laps and interrupted captures are skipped.
Capture is limited to ten minutes per lap. Watch the capture status for skipped laps
or storage errors. Manual recording remains available, and existing runs can be reviewed.

Select your lap and a compatible reference, then choose a map and graph channel.
The map and graphs share a cursor. Tire and suspension channels have a wheel selector.
Select a section to compare the same route positions or open that section in the run graphs.
Pin this lap as benchmark keeps a reference for lap review only; it does not change
the live lap-delta HUD reference. Review timing changes analysis, not capture settings.
Cursor readings use themed cards; expand Wheel readings for individual tire values.
Full-throttle time belongs to the selected section and counts about 98% throttle or more.
New automatic laps save calibrated wheel data when available during recording. Missing
wheel readings in older recordings remain missing; they cannot be reconstructed reliably.

Shift calibration
On a straight with good grip, use a rolling third- or fourth-gear full-throttle pull
from low revs; a first- or second-gear launch is not needed. Hold
through one brief limiter pulse, then upshift and keep accelerating for two seconds.
Wisp saves automatically when the measured curve and confirming shift are complete.
A later qualifying pull can now be used when an earlier, wider pull lacks required evidence.
Recorded gears show collected inputs separately from the shift comparison that still
needs evidence. Recording a higher gear alone does not make an earlier shift target ready.
The existing calibration validation requirements remain in place.
This build corrects normalized-slip rejection and false interruptions when fresh native
data arrives between telemetry receipt and processing. The main calibration label stays
stable while the detailed status explains any remaining missing evidence below it.

This candidate does not automatically write lap diagnostic packet logs.
Automatic lap saving is the separate opt-in control described above.
The checks establish specific regression fixes; calibration and interaction during
actual gameplay still need confirmation with this build.

Shift coverage hotfix
The idle calibration label no longer alternates on fresh native-data refreshes.
A confirmed measured curve can enable supported shifts even if lower-gear
comparisons lack coverage. The saved status lists enabled shifts. Unmeasured
shifts stay off; this does not invent targets or remove the grip/confirmation checks.
For broader coverage, recalibrate from lower revs in any higher gear that grips.
The status gives a numerical lower-RPM coverage goal. On-road behavior still
needs confirmation in your car; these checks do not certify gameplay.
